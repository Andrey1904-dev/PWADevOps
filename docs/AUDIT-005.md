# ТЗ №005 — Telegram linking production bugfix

## Подтверждённые причины

1. **PWA не выполняла переход.** В `src/main.tsx` кнопка «Получить одноразовый код» вызывала `link-telegram`, а затем только отображала `/start <token>`. Ни ссылки, ни открытия Telegram, ни подтверждения не было. Повторный запрос ограничен одной минутой, текст API ошибки скрывался за generic Functions error. В production 16.11 04:13–04:15 UTC: POST link-telegram 200 в 04:13:49 и 04:14:55, повторные 429 в 04:13:52 / 04:14:42 / 04:15:31. Код в БД имел правильный SHA256, не был поглощён, связей было 0. Один webhook 200 в 04:15:03 сам по себе не доказывает успешную привязку: старый обработчик возвращал 200 и непривязанному пользователю. Содержимое личного update не извлекалось; конкретные нажатия пользователя не выдумываются.
2. **Неверный тип запуска Mini App.** `welcomeKeyboard` использовал ReplyKeyboardMarkup с `web_app`. Согласно актуальной официальной документации WebAppInitData при запуске из keyboard button пустое. Наш `telegramApp()` требовал непустое initData, поэтому такой запуск становился обычным PWA без доказанной Telegram identity. Тесты с искусственно заполненным initData не воспроизводили этот контракт Telegram. Источник: https://core.telegram.org/bots/webapps#webappinitdata . HMAC-проверка не является установленной причиной сбоя и не ослаблена.
3. **Сброс контекста после возврата.** AuthGate на focus правильно повторно проверяет сессию и перемонтирует кабинет; выбранная вкладка терялась. Это воспроизведено новым браузерным сценарием возврата. Теперь экран сохраняется в query `screen`, проверка сессии не обходится.

## Новая цепочка

PWA (вошедший пользователь) → «Привязать Telegram» → короткая инструкция и ссылка `https://t.me/PwaDevOps_Bot?start=<64 hex>` → /start автоматически передаётся Telegram → бот показывает inline «Подтвердить привязку» / «Отменить» → webhook проверяет secret, private chat и sender → service-only транзакционный RPC подтверждает исходный user_id → сообщение об успехе и **inline web_app** «Открыть DevOps Quest» → сервер проверяет настоящие initData при запуске → прежний Supabase user_id. Повторной регистрации нет. Эта цепочка протокола реализована; физический клиент не проверен.

Raw capability не отображается как ручная команда и не попадает в серверные логи. Он хранится только в приватном sessionStorage своей вкладки/учётной записи до истечения/завершения. В БД хранится SHA256. Срок 10 минут, один активный запрос, rate limit сохраняется. Callback кодируется в base64url, укладывается в лимит Telegram 64 байта. После открытия запрос закреплён за Telegram chat; чужой callback запрещён. Повтор подтверждения той же связи идемпотентен и не меняет connection_id; потраченный запрос не восстанавливает отозванную связь. Конфликт не перезаписывает чужую привязку. Отмена есть в боте и PWA, отзыв аннулирует pending-запросы. RLS сохранён, новые RPC доступны только service_role.

Старый Reply Keyboard удаляется при техническом /start, временное сообщение уборки удаляется. Дальнейший запуск из inline/menu поддерживает initData. При старом способе запуска с пустым initData показана понятная ссылка для повторного запуска; пустые данные не используются для авторизации. Ошибки TTL/конфликта/отмены/сети/429 объясняются по-русски. Если приложение Telegram не открылось, есть обычная HTTPS-ссылка и инструкция Open in Telegram. PWA проверяет статус при focus/visibility и каждые 5 секунд. При блокировке бота связь не считается активной, но кнопка её отзыва остаётся доступна. Напоминания автоматически не включаются.

- `supabase/functions/link-telegram/index.ts`: авторизованная выдача deep link, отмена, безопасные коды ошибок.
- `supabase/functions/telegram-webhook/index.ts`: preview/confirm/cancel, проверка отправителя, очистка старой клавиатуры, диагностика.
- `supabase/functions/_shared/bot-ui.ts`: inline onboarding, прежние быстрые действия/уведомления сохранены.
- `supabase/functions/_shared/link-flow.ts`: компактный callback, сообщения, безопасный structured logging.
- `supabase/functions/telegram-auth/index.ts`: диагностические коды initData, прежний HMAC/TTL/session flow сохранён.
- `supabase/migrations/20261116042546_telegram_link_confirmation.sql`: additive поля, service-only RPC и аннулирование запросов при отзыве. Существующие профили/миссии/прогресс не заменяются.
- `tests/database.test.ts`, `supabase/functions/tests/handlers_test.ts`, `e2e/app.spec.ts`, `e2e/auth.spec.ts`: негативные сценарии, callback, возврат, ошибки, отсутствие initData.

**Граница доказательств:** HTTP endpoints, Supabase/Auth/RLS настоящие; webhook updates и initData в аудите синтетические, ID вне допустимого Telegram диапазона, сообщения реальным людям не отправлялись. Браузерные E2E используют API-адаптеры и не являются native Telegram/iPhone. Проверка пользовательского сценария на настоящем устройстве остаётся обязательной. Предыдущие тесты не выдаются за неё.

Structured logs: `component=telegram_link`, `stage=issue/prepare/confirm/cancel/init_data/reply`, `code`, статическая техническая `reason` либо код PostgreSQL/Telegram API. Токены, initData, JWT, пароли, body запроса и Telegram ID не логируются.

## Проверка на iPhone после deployment

1. Полностью закройте старую Mini App. Откройте production PWA в Safari/установленном приложении, обновите версию и войдите в прежний аккаунт.
2. Настройки → **Привязать Telegram** → **Открыть Telegram-бота**. Если Telegram показывает «Начать», нажмите её. Не вводите команды и не копируйте коды.
3. В сообщении бота нажмите **Подтвердить привязку**. Должно появиться подтверждение и **Открыть DevOps Quest**. Если сообщение не пришло, проверьте интернет/не заблокирован ли бот; сообщите время попытки без отправки ссылок/токенов.
4. Вернитесь в Safari: ожидается **Telegram подключён**, текущая миссия и прогресс прежние. Обновление при возврате, резервно — за 5 секунд.
5. Нажмите **Открыть DevOps Quest** под сообщением бота. Должен открыться прежний кабинет без логина. Закройте и повторно откройте через меню бота — тот же аккаунт.
6. При желании проверьте отмену нового запроса / отзыв существующей связи в PWA. После отзыва новый автоматический вход должен быть запрещён. Для восстановления создайте новую ссылку; старые кнопки её не восстанавливают.

Если браузер не передал переход в Telegram, используйте HTTPS fallback из блока привязки, затем Open in Telegram. Старыми Reply Keyboard кнопками запуска не пользоваться; новый /start по ссылке автоматически убирает их. Настройка Supabase email redirect — отдельное ограничение предыдущего ТЗ, этим исправлением не маскируется.
