# Аудит ТЗ №002 — 15.11.2026

## Выполнено

- Сохранён существующий React/TypeScript/Vite проект. Production Pages восстановлен повторным deployment после включения Pages владельцем. Base path `/PWADevOps/`.
- Общие компоненты PWA/Mini App: Telegram SDK, темы, expand/ready, Back, мобильная навигация и safe areas.
- initData проверяется сервером: HMAC SHA-256, дубли ключей, срок 5 минут и допуск будущего 30 секунд. Telegram ID берётся только из проверенной подписи.
- Автовход использует существующий `telegram_connections.user_id`. Сервер создаёт одноразовый Auth link для существующего пользователя, проверяет OTP сам и возвращает пользовательскую сессию. Service role не попадает в браузер. Неизвестная привязка требует входа и явного связывания, новый Supabase user автоматически не создаётся.
- Выданный session_id регистрируется вместе с поколением привязки. Отзыв сразу блокирует RLS и привилегированные write RPC, а не только следующую авторизацию. Повторная привязка не оживляет старый JWT. Обычная PWA password-сессия сохраняет права. Mini App проверяет отзыв каждые 5 секунд в открытом окне и при возврате на экран; серверный запрет действует сразу. Офлайн-клиент узнаёт об отзыве после восстановления сети.
- Бот управляется кнопками. Сложные экраны — Web App; подтверждение решения отделено от проверки знаний. Устаревшие callback не могут завершить другую миссию. В меню команд оставлен технический /start.
- XP: 50 за решённую миссию, ещё 50 за проверенную, 200 за проверенного босса. События уникальны по `(user_id,event_key)`, клиент не имеет права их вставлять. Время не выдаёт XP и не подтверждает знания. Уровень: 500 XP. Серия — дни с положительным временем практики.
- Персональный 2/2 от 17.11.2026, 35/150 минут, мало сил 10–15 минут, гибкая недельная цель 660 минут. Ручные смены/минуты/миссии, перенос, больше времени, восстановление плана. Нагрузка мягко адаптируется по последним фактическим занятиям того же типа дня. Босс удерживается до выходного, если рабочий день не выбран явно.
- Серверные уведомления учитывают IANA timezone, рабочие окна, дни недели, quiet hours, opt-in, completed sessions, отдых, snooze, dedupe/TTL/claim и ограниченные retries. Неопределённая сетевая доставка не повторяется вслепую. Логи фиксируют успех, блокировку и ошибки.
- Добавлены управляемое обновление PWA, apple-touch-icon, ErrorBoundary с экспортом исходных локальных данных и защита от белого экрана.
- Исправлены задержка первой загрузки профиля после входа и блокировка outbox промежуточными значениями timezone/часов при наборе текста. Новые правки во время sync сохраняются.
- Bundle разделён: Supabase vendor ~216 KB, основное приложение ~288 KB (gzip суммарно ~147 KB), без предупреждения chunk >500 KB.

## Автоматические проверки

На момент подготовки релиза: 36 unit/PostgreSQL/outbox/adaptive тестов, 13 Deno Edge-тестов, 16 Playwright сценариев (desktop + mobile). TypeScript, ESLint, production build прошли.

PGlite использует реальный PostgreSQL для миграций/RLS/RPC, но не заменяет Supabase Auth/Vault/Cron. Telegram Back/theme и браузерный login fixture в E2E используют явно тестовые адаптеры. Скрипт `scripts/production-browser-check.mjs` отдельно проверяет настоящий production URL без подмены сайта или Supabase.

Живой backend audit использует реальные Supabase Auth/Data/Edge и Telegram Bot API. Подписанные initData для этого теста генерируются **серверным тестовым адаптером** с настоящим server-only token; это не запуск из настоящего клиента Telegram. Проверены первая привязка, повторное открытие, refresh, отсутствие/отзыв связи, чужой user_id, запрет повторного initData, RLS с ещё действующим JWT после отзыва, сохранение PWA доступа и запрет оживления старой сессии после relink. Все временные Auth users удалены. Ответ аудита сохранён в docs/evidence без токенов.

## Ограничения и обязательные завершающие проверки

- Auth redirect production URL требует настройки в Dashboard. Диагностическая строка об этом не считается успешным assertion.
- Реальная доставка пользователю не проверена при отсутствии подтверждённого chat ID. Запланированное уведомление, Mini App в нативном Telegram и установка на физическом iPhone остаются пользовательскими проверками.
- Telegram Bot API не поддерживает идемпотентный sendMessage key. Для неопределённого network timeout выбран возможный пропуск вместо потенциального дубля.
- Полный npm audit содержит low в dev-цепочке Workbox/deepmerge; production audit — 0. Critical/high/moderate отсутствовали при последнем audit.
- SECURITY DEFINER предупреждения относятся к намеренным authenticated RPC. Они проверяют auth.uid/session_allowed, имеют пустой search_path и закрыты для anon; private/session/service RPC не принимают произвольный клиентский user_id. Аудит не объявляется «нулём предупреждений».

Проверка production в CI сверяет HTML build marker с GITHUB_SHA, доступность JS, manifest scope/start_url и Service Worker. Ошибки останавливают job. Отчёт production-health доступен в артефактах workflow.
